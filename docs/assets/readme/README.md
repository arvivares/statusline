# README assets

## App Store download QR

[`app-store-qr.svg`](app-store-qr.svg) links directly to the public
[Statusline App Store page](https://apps.apple.com/app/statusline/id6807851320).
It has no tracker, redirect service, expiration or pairing credentials.

The QR uses high error correction (H), dark modules on an opaque white background
and a four-module quiet zone. Its central badge reuses the exact vectors from the
[official icon](../../../branding/statusline-icon.svg), with a one-module white
gap around it. The generator rejects overlaps with reserved QR patterns. These
checks do not replace scanning the final image after changing its layout.

Both READMEs display it at 245 px and include a clickable App Store link for
visitors already using their phone. The SVG remains sharp at other display sizes.
This public download QR is unrelated to the private, short-lived pairing QR
generated by the companion.

The [website](../../../apps/web/README.md#descarga-para-iphone) imports this same
SVG directly into its production build, without maintaining a separate copy.
Its download card displays the QR at 245 px on desktop and 196 px on mobile,
with a direct App Store button and localized English/Spanish instructions.
Website CI also validates changes to this shared asset and checks the bundled
SVG against the source in both generated language pages.

Regenerate or check from the repository root, using the existing locked desktop
dependencies (no application build is needed):

```sh
npm ci --prefix apps/desktop
node scripts/generate-download-qr.mjs
node scripts/generate-download-qr.mjs --check
```

Repository quality CI checks that the committed QR matches the destination and
current official logo. After changing the destination, logo or layout, scan a
rendered copy and verify the exact URL before publishing.

Validation on 9 September 2026: rendered the final SVG with the locked brand
renderer and decoded it with Apple Vision at 196, 245, 392, 490 and 980 px.
All five returned the exact App Store URL, including the central logo. This is
software-decoder verification, not a physical-camera or print test.

## Android download section

Both READMEs reserve an Android section marked **Coming soon on Google Play**.
Do not add a store QR or imply public Play Store availability until approval is
confirmed. Once approved, add its verified public URL and generate a separate
branded QR, then update the English and Spanish sections together. This does not
prevent downloading the existing beta APKs from GitHub Releases.
