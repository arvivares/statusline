# Statusline 0.1.39 Beta

Claude Code joins Codex and Antigravity in the mobile apps and widgets. Only
services published by your paired Companion appear; existing pairings, encrypted
readings and notification preferences are preserved.

## What's changed

- Android recognizes **Anthropic · Claude Code**, with five-hour and weekly
  quota windows when reported. Focus on Claude or keep it in the watchlist.
  Missing or unavailable quota is not presented as 0% or 100%.
- Three-service widgets retain the Still Signature design and white final meter
  segment. Medium widgets fit both secondary services; compact Android widgets
  retain the 4 × 1 focused default.
- The iOS source candidate adds the same Claude support and fixes both optional
  notification switches reverting after system permission is accepted. Pending
  APNs/Firebase/relay registration is visible and retried while the app is active.
  Permission denial, opt-out and independent category choices remain respected.
- The existing services-v1 schema and opaque relay already carry Claude. No
  relay deployment, database migration, pairing reset or extra credential access
  is required. Older mobiles continue ignoring unknown provider IDs.

## Distribution

Windows EXE/MSI, Linux AppImage/DEB/RPM, universal macOS DMG/PKG and Android
**0.1.39 (37)** APK/AAB are built from this signed tag. Android requires Android
7/API 24, retaining Google Play automatic-protection compatibility. GitHub
publication is configured as **Latest**; the product remains beta.

Windows installers remain **unsigned previews without Authenticode**.
SmartScreen or organizational policy may warn or block them; do not disable
security protections. Linux signatures, macOS Developer ID signing and
notarization, Android signing and updater signatures remain mandatory.

Companion has no collector or relay runtime change in this release. Its version
is coordinated with the mobile candidate; existing supported Companion builds
can already publish Claude through the documented status-line bridge.

iOS **1.1.4 (13)** is a source candidate, not an IPA or App Store update delivered
by this workflow. Its signed archive, TestFlight testing of the new runtime and
subsequent App Store submission are separate. Google Play beta submission is
also separate from GitHub APK/AAB availability; this tag does not claim store
approval or propagation.

## Validation

- Local Swift unit tests: 55 definitions / 113 invocations passed, in both EN
  and ES. Native iOS UI tests passed in both languages, including Claude focus,
  weekly/five-hour selection and the two-service watchlist.
- Android: 42 unit tests and release lint passed. Shared synthetic fixtures
  cover malformed readings, unavailable/removal states, replay/channel isolation
  and legacy Codex compatibility.
- Notification regressions cover both categories, permission denial, delayed
  APNs/Firebase registration, relay failure/recovery and opt-out/disconnect races.
- PR CI, release preflight, installer smoke tests, final signatures, complete
  inventory, checksums and updater metadata are mandatory before publication.

## Known beta limitations

Simulator mocks do not establish physical iPhone push delivery. The new signed
iOS binary still needs affected-device testing before production submission.
See the [mobile validation record](../../validation/mobile-claude-notifications.md).

Widget refresh and push delivery remain best effort and subject to operating-system
scheduling. Existing five-minute Companion collection is unchanged.
