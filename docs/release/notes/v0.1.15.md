# Statusline 0.1.15 Beta

This candidate improves refresh ownership and makes public privacy and support
information independent of the relay. Existing Data Plane styling, Codex desktop
discovery and the encrypted v1 pairing protocol are preserved.

## What's changed

- The Tauri companion reads Codex on a native Rust timer, immediately and then
  every five minutes while running on an awake computer. Hiding its window no
  longer leaves that schedule dependent on the WebView. Concurrent refreshes
  share the same operation; missed ticks do not cause a burst of requests.
- The separate iPhone candidate lets WidgetKit fetch the relay directly with a
  shared reader credential, bounded requests and safe cached-sample fallback.
  Open the app once after updating to migrate an existing pairing. Widgets show
  the age of the sample instead of an unconditional live label.
- iPhone foreground refresh is repeated while the app is active, with guards
  against a late response restoring a disconnected or replaced pairing.
- iOS and Android privacy/support links now use `statusline.inmerzion.io`, with
  Spanish or English according to the app language, regardless of relay settings.
- Privacy, support and data-deletion pages are static bilingual website documents
  with no scripts or analytics. The updated relay redirects legacy information
  URLs by default; its sync API and database contract do not change.

## Downloads

The release pipeline is configured to produce the complete platform set:

- macOS Apple Silicon and Intel: universal DMG and PKG, signed and notarized.
- Windows x64: **unsigned preview** NSIS `.unsigned.exe` and `.unsigned.msi`.
  These do not have Authenticode publisher trust. SmartScreen or organization
  policy may warn or block them; never disable security protections.
- Linux x64: DEB, RPM and AppImage with detached OpenPGP signatures.
- Android: signed APK and AAB, `0.1.15` (`versionCode 11`). Google Play submission
  remains separate. Use the same installation channel when updating; the direct
  APK and Google Play use different signing keys.

iPhone `1.0.1 (5)` is prepared for a separate local archive and manual TestFlight
upload. GitHub Actions does not build iOS, submit it to Apple or replace the
published `1.0 (4)` App Store release.

## Known beta limitations

The five-minute interval is a scheduler target, not a guarantee of a successful
Codex read or publication. Sleep, authentication and network failures can delay
new data. WidgetKit decides actual reload times; requesting a timeline in thirty
minutes does not promise an exact deadline. Android scheduling is unchanged.

Physical-device testing must verify existing-pairing migration, widget updates
without opening the app, sleep/wake, offline fallback and disconnect/re-pair races.
Local unit tests and the ten-minute Rust timer check are not substitutes for
these tests. See [synchronization QA](../../architecture/synchronization.md).

App Server remains experimental. AppImage uses X11/XWayland and depends on
compatible host graphics libraries. Push signaling and desktop auto-update are
not implemented. Publish the website before or alongside the updated relay so
legacy information links do not redirect to pages that are not yet available.

## Verify before installing

The release inventory, signatures, checksums and provenance must pass before the
pipeline publishes this prerelease. Follow the [release runbook](../release-runbook.md)
to verify downloads. Signed checksums do not replace Windows publisher trust.
Preparing these notes does not mean installers have finished or stores have approved
this candidate.
