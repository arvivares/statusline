# Statusline 0.1.32 Beta

Companion now detects newly granted Codex reset credits and can notify your
paired phone. Existing Companion installations can obtain this feature through
the normal signed updater; no manual configuration or re-pairing is required.

## What's new

- **Codex reset credits:** view the available count and expiry when the local
  Codex runtime supplies them. Missing optional metadata never interrupts quota
  synchronization.
- **New-credit alerts:** the first complete reading establishes a silent
  baseline. Only previously unseen credit IDs in later complete readings queue
  an alert; a weekly quota rollover is not treated as a new credit.
- **Optional phone notifications:** enable alerts and grant notification
  permission in a compatible Android or iOS app. Delivery uses the existing
  paired relay and FCM/APNs, without sending account credentials or quota data
  in the notification. Delivery is best-effort.
- **Safe retries:** pending opaque events survive Companion restarts. Repeated
  readings and already acknowledged events do not generate duplicate alerts.
- **Privacy:** raw reset IDs are not persisted or sent to the relay. Local
  history stores salted hashes; quota snapshots remain end-to-end encrypted.
- **Mobile Firebase configuration:** Android and iOS use their respective
  platform-specific client API keys.

## Distribution and compatibility

Includes Windows EXE/MSI, Linux AppImage/DEB/RPM, universal macOS DMG/PKG and
Android `0.1.32 (28)` APK/AAB files, plus signed Companion updater payloads.
The embedded updater key, asset naming, relay v1 contract and existing pairings
are unchanged. Linux DEB/RPM updates still use the package-manager download flow.

Windows installers remain **unsigned previews without Authenticode**.
SmartScreen or organizational policy may warn or block them; do not disable
security protections. Linux package signatures, macOS Developer ID signing and
notarization, Android signing and final-payload updater signatures remain mandatory.

iOS `1.1.2 (11)` is managed separately through TestFlight/App Store. This GitHub
release does not upload or publish either mobile app in its store, redeploy the
relay or alter an existing pairing.

## Validation

- The production reset tracker is included in the lightweight Rust runtime test
  suite on Windows, Linux and macOS, without accessing credentials or accounts.
- Regression cases cover silent baselines, new IDs with unchanged counts,
  duplicate readings, disappearance/reappearance, weekly rollover, partial or
  unavailable data, persistence, restart and acknowledgement. The original
  enum-update test compilation error is corrected.
- A read-only local Codex check confirmed reset-credit metadata availability.
  Android notification delivery and production APNs delivery to TestFlight
  `1.1.2 (11)` were observed on physical devices on this delivery track.
- These checks do not prove detection of a future OpenAI credit grant. After
  updating Companion, its first complete reading is the baseline; a subsequent
  real grant is still needed to verify that full automatic path.
- Native cross-platform builds, installer smoke tests and release inventory,
  signatures and provenance must pass before the pipeline publishes this release.

## Known beta limitations

- New-credit detection requires a complete list of credit IDs from Codex.
  Count-only or partial responses can be displayed but do not trigger alerts.
- Alerts require a compatible paired mobile build with notification permission
  enabled. OS delivery is best-effort, not a guarantee of immediate notification.
- Windows packages remain unsigned for Authenticode; existing security warnings
  still apply. Direct in-app installation is not available for Linux DEB/RPM.
