# Statusline 0.1.28 Beta

Companion settings are now organized around your installed services, with the
same compact Still Signature design. Installers are built from the signed
`v0.1.28` tag; preparing these notes does not publish them.

## What's new

- A single **Services** tab groups Codex, Antigravity and Claude Code in
  expandable sections. Only detected or configured services appear by default;
  additional setup is available when needed.
- Service status, automatic discovery and advanced source settings are grouped
  together. Pending Antigravity edits survive background refreshes and tab
  changes; Claude connection errors remain visible until resolved.
- **Mobile sync** stays in its own tab, keeping private pairing controls
  separate from agent configuration. Existing accounts, saved paths, pairing
  keys, encrypted snapshots and automatic updates are preserved.
- English and Spanish labels and keyboard navigation follow the new structure.
  Android `0.1.28 (24)` includes the updated shared catalog; its quota, QR,
  pairing and widget behavior is unchanged.

## iOS source changes — separate delivery

The repository also removes the iPhone's manual `/status` editor and its obsolete
actions and text. Fixed local demos and past samples remain readable, and pasting
a private pairing link remains an alternative to scanning a QR. The demo cannot
overwrite a paired account. Android already had no manual quota editor.

These iOS changes are **not yet distributed on TestFlight or the App Store**.
App, widget and test sources passed Swift typechecking, but native build and UI
execution need the missing local Xcode iOS platform component. A new iOS build,
device validation and refreshed store screenshots are still required. The
recorded iOS `1.1.0 (9)` has not been replaced by this GitHub release.

## Known beta limitations

- Companion frontend tests, production build, localized browser interaction
  checks and release configuration checks passed during preparation. Native
  platform builds, installer smoke checks and signature verification are required
  before the pipeline publishes the installers. Browser checks do not replace
  physical-device or window-manager testing.
- Windows EXE/MSI files remain **unsigned previews without Authenticode** and
  contain `.unsigned` in their filenames. SmartScreen or organizational policy
  may warn or block installation. Do not disable security protections.
- Linux package signatures, macOS Developer ID signing/notarization, Android
  release signing and signed updater payloads remain required. Existing updater
  filenames, manifest format and verification keys are unchanged.
- Google Play submission is separate. The APK can be installed directly; the
  AAB is provided for Google Play and cannot be installed directly. No relay
  redeployment is needed, and website deployment is managed separately.

## Verify before installing

Follow the [release verification guide](../release-runbook.md#independent-verification)
before installing. Never share private pairing links or agent credentials.
