# Statusline 0.1.13 Beta

This maintenance beta fixes the Linux AppImage blank-window issue while preserving
the Data Plane interface, unified branding and system-selected English/Spanish language.

**Windows testing preview:** this beta also includes **unsigned** NSIS and MSI installers
while SignPath Foundation onboarding is pending. These files have **no Authenticode
signature** and are labeled `.unsigned.exe` / `.unsigned.msi`. SmartScreen may warn or
block them. Verify the signed checksums and GitHub provenance; these do not establish
Windows publisher trust. Do not disable security protections to install the preview.

## What's fixed

- AppImage uses the host's Wayland libraries alongside its graphics stack, resolving
  the reported `EGL_BAD_PARAMETER` startup failure on Ubuntu 26.04.1.
- The launcher limits GIO module loading to its bundled modules, retaining TLS while
  avoiding the incompatible host GVFS module and `g_task_set_static_name` error.
- Packaging validates the complete adjusted payload before signing. Linux CI now
  requires a real frontend-to-backend readiness handshake for both DEB and AppImage
  on Ubuntu 22.04 and revalidates the same signed packages on Ubuntu 24.04.
- Smoke checks distinguish their own shell harness from an already running app.
  Diagnostic tools and their privacy precautions are versioned in the repository.

The [affected-machine confirmation](https://github.com/arvivares/statusline/issues/18#issuecomment-5562928890)
reports stable rendering with the signed candidate on Ubuntu 26.04.1, XFCE/X11 and
Mesa 26.0.8. See the [diagnostic record](../appimage-diagnostics.md) for the exact
candidate digest, evidence and coverage limits. Published 0.1.12 assets are unchanged;
this release builds new installers from its own signed tag.

## Downloads and updates

- Windows x64: NSIS `.unsigned.exe` (recommended per-user installer) and `.unsigned.msi`.
- Linux x64: DEB, RPM and AppImage, each with a detached OpenPGP signature.
- macOS Apple Silicon and Intel: universal DMG and PKG, signed and notarized by Apple.
- Android: signed APK for direct installation and AAB for Google Play (`versionCode 9`).

macOS and Android are rebuilt at the synchronized version with no new functional
changes. Pairing, existing data and the encrypted relay protocol are unchanged.
Install from the same distribution channel as your existing installation. The direct
APK and Google Play use different signing keys; switching between them requires
uninstalling and pairing again. The pipeline does not submit the AAB to Google Play.

iPhone remains `1.0 (4)` with manual App Store Connect distribution. This release
does not compile iOS, upload to TestFlight or change the App Store submission.

## Verify before installing

The release includes `RELEASE-MANIFEST.json`, `SHA256SUMS.txt`, its detached signature
and the Linux verification key. Complete inventory, Linux signatures, macOS trust,
checksums and GitHub build provenance must pass before publication. See the
[release runbook](../release-runbook.md) for verification commands.

## Known beta limitations

- The physical-machine confirmation covers the reported rendering bug, not complete
  pairing, sync, keyring, tray or restart regression testing. CI readiness checks do
  not prove physical-GPU rendering or interaction on other machines.
- AppImage still uses X11; Wayland sessions need XWayland. The host must provide
  compatible Wayland libraries. This is not a guarantee for every Linux distribution
  or GPU. Host GVFS remote-filesystem integration is not promised.
- Windows preview installers are not Authenticode-signed. Signed Windows releases
  remain pending SignPath Foundation; this is an explicit beta policy, not a fallback
  after a signing failure. Linux, macOS and Android retain mandatory signing.
- Mobile synchronization is foreground or user initiated; APNs/FCM notifications and
  automatic desktop updates are not implemented.
- The hosted relay uses Cloudflare Workers and D1; the self-hosted Linux adapter
  remains planned. Codex App Server is experimental.
