# Statusline 0.1.22 Beta

Release candidate: optional Antigravity Google quota in Companion, with the
existing Codex relay contract preserved. Preparing this candidate is not evidence
that installers have been built, signed, published or submitted to a store.

## What's changed

- Add Antigravity from Settings → Add service. Choose the Desktop installation
  or AGY CLI explicitly; Statusline never assumes they use the same account.
- Only Gemini weekly and five-hour quotas are collected. Antigravity's Claude
  and GPT allowances are discarded before reaching the UI.
- The compact Still Signature view shows only configured, installed services.
  No AGY placeholder appears for existing Codex-only users, and Claude is not
  offered. A configured service's temporary failure is visible as unavailable.
- An independent Rust scheduler/cache reads Google quota every five minutes
  while the computer is awake and Companion is running, including when hidden.
  Focus/manual reads reuse samples younger than 60 seconds. Codex refresh and
  publication do not wait for Google. No added relay polling or publication.
- Desktop collection can start its own short-lived bundled native runtime with
  the vendor's window closed. It does not launch the Electron UI or an agent turn.
  AGY CLI uses the documented read-only `/usage` command after a version guard.
- EN/ES copy follows the OS language, with English fallback. The two-service
  view retains the 340 × 500 window, restrained type and white terminal stripe.

## Compatibility and upgrade

Antigravity is **Companion-only** in this release. Android/iPhone apps and widgets
still show Codex. The relay protocol, `schemaVersion: 1`, Codex-only plaintext,
AES-GCM AAD, endpoint, secure-store names, channel tokens and pairing QR are
unchanged. No migration, relay deployment, reset or re-pairing is required.
Removing AGY changes only its local source preference; it does not disconnect a
mobile device, sign out of Google or delete vendor data.

The release inventory still includes macOS DMG/PKG, Windows NSIS/MSI, Linux
AppImage/DEB/RPM, and Android APK/AAB. Android's package version is aligned to
`0.1.22` (`versionCode 18`) for the existing pipeline; it has no new AGY UI or
protocol. iOS delivery remains separate and is not rebuilt by the tag workflow.
Google Play/TestFlight/App Review submissions are not part of this change.

Windows remains an **unsigned preview**: updater signatures verify payload
integrity, not Authenticode publisher trust. SmartScreen or organizational policy
may warn or block installation. Do not disable security protections.

## Known beta limitations

Production collector checks on macOS returned real Google-only quota from AGY
CLI 1.2.3 and Desktop 2.13.0's native runtime. Runtime/parser tests cover invalid
data, version guards, disabled defaults, setting preservation and old relay
cryptography; frontend tests cover configured-only visibility and late events.

Desktop's local API is internal, not an officially supported public quota API.
Windows/Linux code paths still need CI and real account/device validation.
Their trusted-installation requirement is explicit; this adapter does not claim
cross-platform publisher-signature verification. macOS verifies Google's signer.
The successful local account samples had full quota; non-full/reset behavior
has fixtures but still needs live consumption verification.

Before publishing: pass native CI on all three OSes; test the actual installers,
updater, hidden-window cadence, Google auth absence/timeouts and existing mobile
pairing preservation. A frontend preview and isolated collector probe are not
an installed-Companion end-to-end test.

## Verify before installing

Use the [release runbook](../release-runbook.md#independent-verification) for
platform signatures, updater signatures, checksums and build provenance. Never
use a vendor credential or private pairing link as a diagnostic fixture.
