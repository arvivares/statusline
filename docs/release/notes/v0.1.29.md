# Statusline 0.1.29 Beta

Companion now selects the general Codex quota automatically, fixing an incorrect
0% remaining reading when a separate model or reserve limit was exhausted.
Installers are built from the signed `v0.1.29` tag after release validation.

## What's fixed

- Read the `codex` bucket by its identity, not the most exhausted bucket in the
  account. Separate limits such as `gpt-reserve` and `codex_spark` no longer
  replace the general Codex quota. No manual selection or new settings are needed.
- Keep the weekly quota, short window and reset times from the same Codex
  snapshot. A genuinely exhausted Codex quota still reports 0%; missing or
  invalid Codex data is never replaced by another service's quota.
- Preserve the compatibility snapshot for older Codex runtimes, while ignoring
  unrelated bucket formats that do not affect the selected Codex quota.
- Remove the obsolete "most restrictive limit" explanation in both languages.
  Discovery, refresh scheduling, saved settings and pairing remain unchanged.
- Send the corrected quota through both existing mobile snapshot formats.
  Existing iPhone and Android apps receive it through normal synchronization
  after the Companion is updated, without re-pairing or a relay deployment.

## Distribution

This GitHub release includes Windows, Linux and macOS Companion installers and
Android `0.1.29 (25)` APK/AAB files. Android only removes unused shared translation
entries; its quota, QR, pairing and widget behavior is unchanged. The APK can be
installed directly; the AAB is for Google Play and is not directly installable.

iOS remains recorded as `1.1.1 (10)`. This release does not upload a new iOS build,
replace a store submission, deploy the website or deploy the relay. Google Play
and App Store distribution are separate from GitHub Releases.

## Known beta limitations

- Production Rust tests cover bucket identity, exhausted reserves, genuine Codex
  exhaustion, compatibility fallback, malformed data and both mobile projections.
  A read-only live Codex query passed on macOS. CI validates the shared logic and
  native builds on all desktop platforms; real Windows/Linux account sessions
  and a final installed-package upgrade still require device verification.
- Windows EXE/MSI files remain **unsigned previews without Authenticode**, marked
  `.unsigned`. SmartScreen or organizational policy may warn or block installation.
  Do not disable security protections.
- Linux package signatures, macOS Developer ID signing/notarization, Android
  signing and final-payload updater signatures remain mandatory. Existing updater
  filenames, manifest format and verification keys are preserved.
- Mobile background/widget scheduling remains controlled by the operating
  system. This fix corrects the source quota; it does not change refresh timing.
