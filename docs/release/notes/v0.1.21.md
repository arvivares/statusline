# Statusline 0.1.21 Beta

A maintenance release for Companion and Android, keeping the compact Still
Signature interface and existing pairing and synchronization protocol.

## What's changed

- Companion updates its HTTP, filesystem and packaging dependencies: reqwest
  0.13.5, dirs 7.0.0, uuid 1.26.1 and flate2 1.1.10. Production and runtime-test
  dependency versions are checked together to prevent drift.
- Android updates the Compose compiler plugin to 2.4.20 and the Compose BOM to
  2026.09.00. There is no intentional mobile layout or pairing-flow change.
- Desktop and website builds use Vite 8.3.0. The relay's development tools move
  to Wrangler 4.131.0 and Vitest 5.0.0; the wire protocol is unchanged and this
  release does not deploy a relay service.
- The website source now uses current, language-matched Still Signature app and
  settings captures. Website deployment is separate from these installers.
- Dependency updates now isolate major upgrades, validate production frontend
  builds and keep the Rust runtime-test dependencies aligned with the app.

## Downloads and upgrade notes

- macOS: signed and notarized universal DMG and PKG for Apple Silicon and Intel.
  Users on 0.1.17/0.1.18 still need one manual DMG or PKG installation to receive
  the updater fix introduced in 0.1.19.
- Windows x64: **unsigned preview** NSIS `.unsigned.exe` and `.unsigned.msi`.
  Updater signatures verify payload integrity, not Authenticode publisher trust.
  SmartScreen or organizational policy may warn or block installation. Never
  disable security protections.
- Linux x64: AppImage, DEB and RPM with detached OpenPGP signatures. AppImage
  supports the companion updater; DEB/RPM updates use the package manager.
- Android: signed APK and AAB, `0.1.21` (`versionCode 17`). Update through your
  original distribution channel; Google Play delivery is a separate submission.

GitHub publication does not submit builds to Google Play, TestFlight or App
Review. There are no iOS source changes since 0.1.20, so this maintenance release
does not rebuild or replace the separately delivered iOS app. Existing mobile
pairings use the same encrypted relay protocol; no re-pairing is required by
these changes.

## Known beta limitations

The merged dependency updates passed frontend, relay, Android tests/lint and
Windows/macOS/Linux runtime checks. Physical QA of the Android dependency
candidate on an SM-G950F running Android 16 covered launch, English/Spanish,
unsupported-language fallback, the demo quota view, camera permission and
scanner cancellation, and a 4 × 1 demo widget that opens the app. The original
production pairing was left untouched.

That device check used the CI debug dependency candidate, not the final signed
0.1.21 build. Optical QR decoding, a new real pairing, a live signed macOS
upgrade with pairing preservation, and clean-machine Windows desktop-only
discovery remain separate device checks. CI smoke tests do not replace them.

The signed-tag pipeline verifies the complete asset inventory, applicable
platform signatures, updater signatures, checksums and build provenance before
