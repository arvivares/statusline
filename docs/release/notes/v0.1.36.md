# Statusline 0.1.36 Beta

Dependency maintenance and a Linux packaging compatibility correction.
Existing accounts, discovered services, encrypted synchronization, pairing and
notification preferences are preserved.

## What's changed

- Align native Tauri and its JavaScript API/CLI on **2.12.1**, with native and
  JavaScript dialog **2.8.1**. Preflight still rejects version drift.
- Adopt official **tray-icon 0.25.1**, including the macOS 27 click-forwarding
  correction, instead of the temporary local backport. Left-click toggling,
  right-click menus and outside-click hiding are preserved.
- Upgrade **minisign-verify to 0.3.0**, without changing the embedded updater
  public key or signing format. Build tooling, Vite, Vitest, relay types and
  reviewed Gradle CI actions are also updated.
- Adapt AppImage inspection and its isolation hook to Tauri CLI 2.12.1's
  normalized **usr/lib/gio/modules** layout. Bundled TLS, host Wayland library
  resolution, symlink/ELF checks and byte-for-byte repacking checks remain required.
- Explicitly preserve the tested **X11/XWayland** backend in the Statusline hook;
  the new upstream GTK hook no longer forces it. This is not a claim of native
  Wayland support. Diagnostics accept only the two reviewed legacy/current GIO layouts.
- Retain **Android 6/API 23** and WorkManager **2.11.2**. WorkManager 2.12.0 was
  not adopted because it requires Android 7/API 24.

The 0.1.35 candidate failed its Linux layout gate and was never published. Its
signed tag is retained unchanged; this new version carries the source correction.

## Distribution

Windows EXE/MSI, Linux AppImage/DEB/RPM, universal macOS DMG/PKG and Android
**0.1.36 (33)** APK/AAB are built from the same signed tag. Companion updater
signatures cover final payloads. Labels do not rename assets or change updater URLs.
GitHub publication is configured as **Latest**, while product maturity remains beta.

Windows installers remain **unsigned previews without Authenticode**.
SmartScreen or organizational policy may warn or block them; do not disable
security protections. Linux signing, macOS Developer ID signing/notarization,
Android signing and updater signature gates remain mandatory.

iOS stays recorded at **1.1.3 (12)**. This release does not upload to App Store
Connect or Play Console, deploy the relay, migrate D1 or replace live pairings.
No new telemetry, quota source or push-delivery behavior is introduced.

## Validation

- Dependency PR CI passed native checks and production-module runtime tests on
  macOS, Windows and Linux. The isolated macOS 27 tray probe passed OS-generated
  click/menu/outside-click tests without loading real agent settings or credentials.
- Packaging fixtures check the normalized layout, retained TLS, hostile inherited
  environment, relocated paths, symlinks, unexpected aliases, missing modules,
  corrupted repacking and rejection before input mutation. Diagnostic fixtures
  retain legacy support and reject ambiguous layouts or missing TLS.
- The pipeline must additionally build the real bundles, exercise frontend
  readiness on Ubuntu 22.04/24.04, smoke-test installers and verify signing,
  inventory, checksums and provenance before publication.

## Known beta limitations

- Installed-package upgrades, physical Windows/Linux desktop interactions,
  macOS 26 and native file-picker QA are distinct from CI and fixture tests.
- Existing five-minute collection cadence and best-effort push limits apply;
  Linux DEB/RPM updates use package managers. Existing strict-Clippy warnings in
  unchanged code are not represented as resolved by this release.

## Verify before installing

Follow the [release verification guide](../release-runbook.md#independent-verification)
for checksums, Linux signatures and build provenance. Never share pairing links,
